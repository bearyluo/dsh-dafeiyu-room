# Token 测算

日期：2026-11-01。使用 [DeepSeek 官方离线分词器](https://api-docs.deepseek.com/zh-cn/quick_start/token_usage/) 当日链接的 V4 tokenizer，对插件自身说明、实际注册的普通函数工具定义以及合成房间状态分词。没有读取私人聊天或发送模型请求。

| 内容 | 示例 Token 数 |
|---|---:|
| 环境说明与当前状态 | 1,016 |
| 两个工具的描述与 JSON Schema | 485 |
| 合计 | 1,501 |
| 一条空闲决策通知，另计 | 79 |
| 三步计划的示例调用，另计 | 43 |
| 一步计划的示例接收结果，另计 | 32 |

状态内容、模型 tokenizer、SDK 工具模式与 API 消息封装会使实际数量变化。这是示例文本的离线计数，不是对所有请求的固定配额。实际以模型 API 返回的 usage 为准。

按约 1,500 输入 Token 计算：原请求输入量为 5,000、10,000、20,000 时，分别约增加 30%、15%、7.5%。计算式为 `插件新增输入 / 原请求输入`。这些百分比不代表全天总 Token 或费用增幅。

观看画面、安卓浮窗、逐帧动画、离线睡姿和天气轮询均不调用模型。默认每天最多 12 次空闲自主唤醒；一次唤醒可触发工具及后续模型步骤，每个请求仍携带宿主当前上下文。

例如假设宿主输入为 10,000 Token，12 次唤醒各仅有一次请求，则增加的自主请求输入约 `12 × (10,000 + 1,500 + 79) ≈ 139,000` Token，尚未包含输出或工具后续请求。现实用量可能更高，也可能因睡眠计划与额度未用满而更低。

减少用量可以延长 `cooldownMinutes`、降低 `maxDailyDecisions`；设为 0 停止空闲自主唤醒。不要仅通过动画帧率推算 Token。缓存可能影响价格，但不应将缓存后的费用变化冒充 Token 净增量。

复现文本：`node scripts/audit-token-overhead.mjs build/token-audit/texts`。再用官方页面链接的离线 tokenizer 对生成的 UTF-8 文本编码；本次未加入特殊消息边界 token。该脚本使用临时合成状态，不连接模型。
